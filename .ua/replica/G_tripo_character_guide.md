# 人物建模引导（Tripo AI → Blender → Unity）

写于 2026-11-27。依据：制作人指令（人物预设图已完成，要拿到 Tripo AI 里建模），设计文档 V1.5 第 10.1、10.2、10.9 节和附录 A，Tripo 官方开发者文档（2026-11-27 读取，链接在文末）。

说明两点。第一，主代理还没有看到人物预设图，仓库和 `D:\GameDev` 下都没有找到，所以第 2 节的检查要等制作人把图给过来才能做。第二，Tripo 的参数和价格来自官方文档，主代理没有实际跑过生成，哪个模型对这种画风效果好要试了才知道，文中标了“待试”的地方都是这种情况。

## 0 整体路线

```
人物预设图（正、背、左、右）
  → Tripo 多视图生成（网格 + 贴图）
  → Tripo 自动绑骨（Mixamo 命名）      可选，也可以在 Blender 里绑
  → Blender 清理（缩放到 1.75 m、比例红线、布线、减面、拆分换装层、加骨）
  → FBX 导出 → Unity（Humanoid、卡通材质、极端姿势测试）
```

和设计文档附录 A 的区别只有一处：图生 3D 这一步原来写的是 Rodin，现在换成 Tripo。附录 A 其余部分（Mixamo 骨骼标准、Blender 清理、换装分层、Unity 卡通材质）不变。

## 1 先办的三件事

1. 账号选站。Tripo 有两个站，账号不通用：国际站 `studio.tripo3d.ai`（Stripe 付款），中国大陆站 `studio.tripo3d.com`（支付宝）。选一个，之后一直用它。
2. 必须用付费账号生成正式资产。用户协议 5.2.1 写免费用户的输入和输出的知识产权归 Tripo，5.2.2 写付费用户对输入和输出拥有全部权利并可商用。生成前后把订阅或充值凭证、任务编号截图留存（附录 A 要求留存商用授权凭证）。协议 3.2 另写明输出不保证唯一、不担保不侵权。
3. 确认预设图的来源。设计文档 10.1 写“用 AI 工具把参考立绘转成的 3D 结果只用于研究方向，不进入正式资产”，指的是第三方游戏的立绘。预设图如果是自己出的定稿图就没有问题；如果是拿 QQ 炫舞或街球派对的立绘直接改的，生成结果只能当研究用。

## 2 预设图检查清单

把图发给主代理后逐项核对。不满足的项先改图再生成，比生成后在 Blender 里补救省事。

| 项 | 要求 | 出处 |
|---|---|---|
| 视图 | 正面必须有，至少 2 张；Tripo 有 front、left、back、right 四个位置 | Tripo 多视图文档 |
| 一致性 | 几张图是同一个人物、同一套服装、同样的光照 | Tripo 多视图文档 |
| 格式 | PNG、JPEG 或 WebP，分辨率不低于 256 × 256（实际越高越好） | Tripo 多视图文档 |
| 姿势 | A-pose，手臂离开身体，手指张开，双脚分开 | 附录 A.2.2 |
| 背景 | 白底或纯色底，人物完整不裁切 | 附录 A.2.2 |
| 球拍 | 图里不要拿球拍。球拍是独立资产（10.2 羽毛球专属层），画在手里会和手长在一起 | 10.2.4 |
| 头身 | 6.5 头身，修长、非幼儿化的青年体型 | 10.1 |
| 比例红线 | 头高约 0.27 m（按身高 1.75 m 折算）、腿长不小于身高的 0.48、肩宽约 2 个头宽 | 10.2.3 |
| 遮挡 | 发型、饰品、衣摆不遮挡持拍手和脚下站位 | 10.2 |
| 明暗 | 尽量平涂，少画投影和高光。画了明暗的话生成贴图时开去光照选项试试（见第 3 节） | 待试 |

左、右两个位置指人物的左侧还是画面的左侧，官方文档没有写明，第一次生成时看预览核对一下，方向反了就把两张图对调。

只有一张正面图时，Tripo 有“单图转四视图”功能（10 积分），可以先让它补出其余三面，再人工挑选或修改。自己画的三视图一致性更可控。

## 3 生成参数

两种模型都值得各试一次，结果给制作人对比后再定。

| 方案 | 模型 | 特点 | 适合 |
|---|---|---|---|
| A | Tripo H3.1（API 名 `v3.1-20260211`） | 高精度网格，面数高，之后要重拓扑或减面 | 看造型还原度，当高模参考 |
| B | Tripo P2（API 名 `P2-20260801`） | 原生四边面，低面数，布线干净 | 直接当游戏网格的底子 |

面数目标来自设计文档 10.9：人物 LOD0 12k–18k 三角面。P2 开四边面时 face_limit 的上限是 25,000。一个四边面拆开是两个三角面，按这个换算，四边面数可以设在 6,000–9,000 之间试【待试】；face_limit 在四边面模式下数的是四边面还是三角面文档没有写明，以生成结果的实际面数为准。

| 参数 | 建议 | 说明 |
|---|---|---|
| texture | 开 | 生成贴图 |
| pbr | 关 | 本作在 Unity 里用统一的卡通着色（10.1），只需要底色贴图。CLI 0.9.0 起默认就是关 |
| texture_quality | detailed | 贴图 LOD0 目标 2048（10.9）；8K 的 extreme 没有必要 |
| delight（去光照） | 预设图画了明暗就开，平涂就关 | 只有贴图模型 v3.5 支持。待试 |
| quad | 方案 B 开 | 只有 P2 支持，输出 FBX |
| auto_size | 关 | 尺寸在 Blender 里统一缩放到 1.75 m |
| model_seed、texture_seed | 记下来 | 同样的输入加同样的种子可以复现；只换 texture_seed 可以保持网格不变重出贴图 |
| generate_parts | 不用 | 和贴图、四边面互斥。分件在 Blender 里做，或者之后用分割功能 |

费用（开发者平台按量计价，1 积分 = 0.01 美元；Tripo Studio 网页版的订阅价格主代理没有取到）：多视图生成带标准贴图 30 积分，高清贴图加 10，四边面加 5，高清几何加 20，自动绑骨 25。一次完整尝试大约 45–85 积分。

## 4 两种操作方式

### 4.1 网页版 Tripo Studio（制作人自己操作）

1. 登录选定的站，进入图生 3D，选多视图，把预设图按位置放好。
2. 选模型和第 3 节的参数，生成。
3. 在预览里转一圈看：脸、手指、头发后侧、鞋底、腋下和裆部有没有粘连。
4. 满意后做自动绑骨，骨骼规范选 Mixamo，导出 FBX 或 GLB。
5. 把导出的文件放到 `art_src\character\tripo\` 下（这个目录要等制作人确认 `art_src` 的位置，见 E 报告第 9 节第 18 项），把任务编号和参数记在同目录的文本里。

网页版界面主代理没能打开核对（被验证页挡住），菜单名称以实际界面为准。

### 4.2 命令行或 MCP（主代理代为操作）

官方的 MCP 和命令行页面写明 DeepSeek Harness 有官方插件：在插件管理里搜 Tripo，安装后在浏览器里授权，不需要 API key。主代理没有在本机验证过这个插件。

备用方式是命令行工具 `tripo-cli`。官方文档页写的是 0.9.0 版、要求 Node.js 20 以上；npm 上 2026-11-24 的最新版是 0.11.4，要求 Node.js 22.12 以上。本机 Node 是 26.0.0，满足要求。装的时候以 `tripo docs --llm` 打印出来的说明为准。

```
npm install -g tripo-cli
tripo login --region ov        国际站；大陆站用 cn。浏览器里授权，不要把 API key 贴进对话
tripo doctor                   检查登录、网络、余额

tripo make front.png back.png left.png right.png --model tripo-p2 -p quad=true --dry-run
                               只出计划和估价，不建任务、不扣积分
tripo make front.png back.png left.png right.png --model tripo-p2 -p quad=true
tripo view "@last"             浏览器里看预览
tripo make "@last" --then rig  自动绑骨
```

几个注意点（都来自官方命令行文档）：不指定模型时默认用 P2；H3.1 要写 `--model tripo-v3.1`；PowerShell 里 `@last` 和带逗号的参数要加引号；提交时遇到网络错误或超时不要重复提交，任务可能已经建了，用 `tripo task watch <任务编号> --download` 接着等；产物在 `tripo-out` 目录。绑骨时指定 Mixamo 规范的参数写法文档页没有给出命令行示例，用 `tripo docs --topic commands/process` 查。

## 5 Blender 清理

沿用附录 A.2.2，逐项做，每项做完截图。

1. 导入，统一缩放到身高 1.75 m，脚底在 Z = 0，面朝方向按 E 报告 6.3 节的约定。
2. 放五条高度标尺（0.05、0.70、1.60、1.75、2.55 m），量头高、腿长、肩宽，对比例红线。举拍姿势下持拍最高点对齐 2.55 m，误差 5 cm 以内（要配合球拍，球拍放大不超过 1.1 倍）。
3. 检查肩、肘、腕、髋、膝的布线，不够的地方补环线。
4. 减面到 LOD0 12k–18k 三角面，LOD1 约 60%，LOD2 约 30%。
5. 骨骼：统一 Mixamo 标准（约 65 根），追加球拍骨、前臂扭转骨、次级动画骨 8–16 根，总数不超过 80，每顶点 4 个权重。Tripo 自动绑骨的权重要在这里检查和修。
6. 按 10.2.4 拆分：角色基础层、服装层、羽毛球专属层（球拍、球鞋）。所有部件共用一套骨架。
7. 贴图：只保留底色贴图，LOD0 用 2048。
8. 导出 FBX，设置按 E 报告 6.3 节。

## 6 Unity 导入和验收

1. 导入设置按 E 报告 6.4 节，Rig 选 Humanoid，核对骨骼映射。
2. 套卡通材质：二阶色阶加柔和过渡带、暗部偏暖、边缘光、脸部 SDF 阴影、头发各向异性高光；描边用 inverted hull，屏幕空间 1.5–2 px（10.1）。
3. 极端姿势蒙皮测试：跳杀、蹬跨、鱼跃、反手头顶击球（附录 A.2.2）。
4. 放进白模球场，实战机位下看：人物身高约占屏高 26%，持拍手、拍面、脚下站位不被发型和饰品遮挡。

## 7 现在等什么

1. 制作人：把人物预设图发过来或告知存放位置。
2. 制作人：选 Tripo 的站，确认用的是付费账号。
3. 制作人：选操作方式（自己在网页版做，还是装插件或命令行让主代理做）。
4. Blender 装好并接入（第 5 节要用）。
